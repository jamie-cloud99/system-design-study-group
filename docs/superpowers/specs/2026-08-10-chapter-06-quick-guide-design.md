另外製作一份可在 10 分鐘內讀完的第六章快速版，幫助第一次接觸分散式 Key-Value Store 的讀者先建立整體概念。原始講義 `chapter-06-design-a-key-value-store.md` 保持不變。

## 閱讀動線

### 1. 兩分鐘 Recap

從前端讀者熟悉的 `localStorage` 或快取切入：Key-Value Store 就是用 key 存取 value。先畫出單機模型：

```text
Client -> Memory / Hash Map -> Disk
```

接著只建立三個前提：資料會超過一台機器、機器一定會故障、網路可能延遲或中斷。Recap 不提前教 CAP 等術語。

### 2. 從單機長成分散式系統

用一條簡短演進路線建立全貌：

```text
一台放不下 -> 分片
機器會故障 -> 複製
多份資料可能不同 -> 一致性取捨
多人同時修改 -> 衝突處理
故障節點恢復 -> 資料修復
資料要落到硬碟 -> 儲存引擎
```

讀者先看懂問題順序，再進入個別技術。

### 3. 六個必要概念

每個概念使用相同格式，控制在短段落內：

1. 現在遇到什麼問題？
2. 系統怎麼處理？
3. 這樣做有什麼代價？
4. 一句話記法。

概念依序為分片、複製、CAP 與 Quorum、版本衝突、故障修復、儲存引擎。Vector Clock、Gossip、Hinted Handoff、Merkle Tree、LSM-Tree 和 Bloom Filter 放在對應概念下，先說用途，不展開細節。

### 4. 知識分級

- 一定要懂：為什麼需要分片與複製、CAP 的取捨、Quorum 的重疊直覺、基本讀寫路徑。
- 先知道用途：Vector Clock、Gossip、Hinted Handoff、Merkle Tree。
- 先記一句話：LSM-Tree 讓寫入保持連續，Bloom Filter 幫助跳過一定沒有 key 的檔案。

### 5. 收尾檢查

用一張「問題、解法、代價」表格收斂全章，最後提供三題自我檢查。問題要求讀者用自己的話解釋，不要求背名詞或公式。
