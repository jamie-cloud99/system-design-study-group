先看規模

網路爬蟲・互動講義

第九章・給前端工程師的系統設計讀書會・可在現場一邊討論一邊操作

爬蟲是一個無限迴圈：從種子網址出發，下載頁面、抽出新連結、再把新連結排進待抓清單。抓一頁很簡單，難的是規模：要抓得快、不能搞垮別人的網站、不重複做白工，還要躲開爬不完的陷阱。

平均每頁 500 KB約 500 TB／月
保存 5 年約 30 PB，需要分散式儲存
🏗️ 你的 SPA 對爬蟲來說，可能只是 <div id="root"></div>。爬蟲下載到什麼，才是它能索引的內容。

先看全貌

一個網址會經過哪些元件？

選一種情境，用「下一步」讓小圓點帶你走完。三種結局：成功入庫並產生新網址、因重複內容被丟棄、因網址已見過被丟棄。

一句話：爬蟲的每個元件都在回答一個問題：這個網址能不能抓、抓回來的內容有沒有價值、抽出來的連結值不值得再抓。後面幾節逐一拆開。

現在的問題

單一佇列會把同一個網站灌爆

大站的首頁一次抽出上千個連結，如果全丟進同一個 FIFO 佇列，幾個 worker 會同時打同一個網站。對方受不了，我們也會被封鎖。切換模式，按「下一輪」比較。


      

      

        

          
兩層佇列

          
前置佇列依優先級（PageRank、流量、更新頻率）決定先抓誰。後置佇列每個網站一條，由固定的 worker 處理，兩次下載之間加入延遲。

        

        

          
代價

          
待抓網址可達數億筆，全放記憶體撐不住，全放硬碟又慢。常見折衷是主要資料放硬碟、記憶體保留緩衝區。還要定期重抓，才能維持新鮮度。

        

      

      
一句話：前置佇列管「先抓誰」，後置佇列管「別灌爆同一站」。

排好隊了，下載本身還是慢，而且不一定被歡迎

      

        

          
讓下載又快又有禮貌

          
    
            
  1. 先讀並快取對方的 robots.txt，遵守不許爬的路徑。
    2. 
            
  2. DNS 查詢可能要 10–200 ms，把「網域 → IP」存快取並定期更新。

  3. 依主機名稱把網址分給多台伺服器，用第五章的一致性雜湊分配。
    4. 
            
  4. 設定逾時，慢網站不能拖住 worker。
    5. 
          

        

        

          
代價

          
多機要處理故障與狀態：定期把 Frontier 保存成檢查點，單頁失敗不能拖垮全局。robots.txt 與 DNS 快取過期時，會用到舊資料。

        

      

      
一句話：遵守 robots.txt 是禮貌，也是避免被封鎖的最低成本做法。

同一個網址要怎麼只抓一次？數十億個網址放得進記憶體嗎？

      
內容去重：對頁面內容算雜湊（例如 SHA-1），比對雜湊值，比逐字比較便宜。網址去重：Bloom Filter 用很少記憶體回答「這個網址是否可能見過」。下面用 32 個位元、3 個雜湊函式的小濾網，親手造出一次誤判。

Bloom Filter 的行為

          
說「沒見過」時一定正確；說「見過」時可能誤判。所以不會重複抓取，但少數新網址可能被漏掉。

        

        

          
代價

          
位元越滿誤判越多，標準版本也不能刪除元素。若漏抓一頁的代價很高，要改用精確集合或資料庫，Bloom Filter 只作前置篩選。

        

      

      
一句話：用「可能漏抓一點」換「記憶體省一大截」，爬蟲通常付得起這個價錢。

    


    

      
現在的問題

      
有些網站會產生無窮多個網址

      
🏗️ 想像一個日曆元件，每個月都有「下個月」連結，人看了會停，爬蟲會一直點下去。

      
拖動滑桿，看網址如何越爬越長，以及長度上限（這裡設為 128 字元）何時把它擋下。

      

        

          
          
        

        

        

      

      

        

          
設上限

          
限制網址最大長度、爬取深度與單站頁數；異常網域加入黑名單。動態渲染的頁面可先做伺服器端渲染再解析。

        

        

          
代價

          
很難全自動偵測，需要人工審查。上限設太低會誤殺正常的長網址。

        

      

      
一句話：長度上限是便宜的第一道防線，不是萬靈丹。

自我檢查

      
面試模擬

      

        為什麼爬蟲通常用 BFS 而不是 DFS？單純 BFS 還缺什麼？
        
網頁圖可能很深，DFS 容易鑽進無底洞。BFS 逐層擴散，較容易先覆蓋靠近種子的頁面。但單純 BFS 沒有禮貌與優先級，所以需要 URL Frontier 的兩層佇列。

      

      

        Bloom Filter 為什麼適合 URL Seen？什麼時候不能只靠它？
        
它用很少記憶體就能快速判斷「可能見過」。限制是會誤判，少數新網址被漏抓。當漏抓任何一頁的代價很高，或需要刪除元素時，要改用精確集合或資料庫。

      

      

        DNS 查詢什麼時候會變成瓶頸？怎麼處理？
        
每次下載都做同步 DNS 查詢，而一次要數十到數百毫秒時，吞吐量會被卡住。自建 DNS 快取並定期更新，可明顯降低開銷。

      

      

        你的 SPA 首頁原始 HTML 只有一個空 div，搜尋引擎會看到什麼？
        
只看到空殼，除非爬蟲會執行 JavaScript。主流搜尋引擎能渲染，但成本高、收錄可能延遲。用 SSR 或預先渲染，讓初始 HTML 就有主要內容，比較穩妥。
